## Migration and runtime

Before/after checksums matched for all existing bookings: 32 journeys `9768e5b8ca9f5c0b9a0a5a87d71108c1`, 156 hotel stays `a25fe60025249839d7540fd6cf7c09bf`, and 114 rail bookings `8ca64b8003ab5f41279bd76d87c149a8`. No existing quote or accepted policy was rewritten; no retained table/volume was reset. New fictional test records are deliberately retained.

V1 bookings retain full-cancellation terms. V1 mutations/document access reject modern quote versions so they cannot bypass partial-funding or refund rules. V2 My Trips renders both versions with collected/refunded/pending/outstanding values. Bus replacements are linked, separately paid bookings, not native amendments or net adjustments. Holiday partial cancellation is limited to optional activities after full funding; the sample milestone plan is 30/70 with a 48-hour balance deadline. Cab updates are persisted synthetic stages, not actual GPS or real driver identities.

Remaining access blockers: authorized providers/gateway, valid travel documents, real driver/contact/location feeds, operator IdP/MFA provisioning and an approved AWS deployment target. No cloud plan/apply, dependency upgrade, production benchmark, compliance certification or restore/DR drill was performed in this increment. Notifications/outbox delivery and broader supplier-specific amendments/milestone policies remain separate scope.
